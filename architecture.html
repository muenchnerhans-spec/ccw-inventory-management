Architecture overview

Factory Inventory Management System

A full-stack demo app for a Claude Code workshop. A Vue 3 single-page app talks to a small FastAPI service that serves mock data from JSON files held in memory. There is no database, no auth backend, and no persistence.

System overview

Two local processes. The browser loads the SPA from Vite, then calls the API directly across origins (CORS is open).

Frontend

Vue 3 with Options-style export default { setup() } components. Shared state lives in module-level refs inside composables (singletons), not in Pinia or Vuex.

Shared filter state

useFilters keeps four refs at module level, so every view sees the same values: period, location (warehouse), category and status. getCurrentFilters() maps them to API params (period becomes month).

Internationalisation

useI18n serves locales/en.js and ja.js through t('a.b') with an English fallback. The locale is saved in localStorage and also selects the currency (en: USD, ja: JPY).

Styling

Scoped custom CSS inside each .vue file, with global styles in App.vue. Charts are hand-written SVG. There is no CSS framework installed.

Backend

A single file, server/main.py (309 lines). Handlers filter the in-memory lists with two helpers and return them through Pydantic response_models. Dashboard totals and the report aggregates are computed on each request.

Filter helpers

apply_filters() compares warehouse exactly and category/status case-insensitively; 'all' disables a filter. filter_by_month() accepts YYYY-MM or a quarter key (Q1-2025 to Q4-2025) and matches it against order_date. Inventory has no date field, so the month filter does not apply to it.

Tests

tests/backend/ uses pytest and FastAPI's TestClient (fixture in conftest.py) with files for dashboard, inventory and misc endpoints. Dev dependencies are declared in server/pyproject.toml; runtime dependencies are only fastapi, uvicorn and pydantic.

Data flow

What happens when a user changes a filter, for example Warehouse. The same path serves every filtered view.

  1. Filter changesFilterBar updates a shared ref in useFilters.js. All four filters are global and apply to every page.
  2. Views reactEach view watches the filter refs and reloads its data, usually with Promise.all over several calls. Loading and error states are set around the call.
  3. Request is builtapi.js drops parameters equal to 'all' and sends GET /api/...?warehouse=...&month=... to the hardcoded base URL.
  4. Server filters in memoryThe handler runs apply_filters() and filter_by_month() over module-level lists loaded once at startup.
  5. Response is validatedPydantic shapes the output. If a JSON file changes structure, the matching model in main.py must change too.
  6. Derived data is computedRaw responses sit in refs such as allOrders and inventoryItems. Charts, KPIs and tables come from computed() properties and custom SVG.

Findings from the analysis

Gaps between the frontend and backend found while reading the code.

Missing routes Tasks and purchase orders

api.js defines getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder and getPurchaseOrderByBacklogItem, but main.py has no /api/tasks or /api/purchase-orders routes. App.vue calls getTasks() on load, so that request fails and is only logged to the console. The PurchaseOrder models exist, and purchase_orders.json is an empty list.

Unused code Backlog view

views/Backlog.vue is not imported in main.js, so it has no route. Backlog data reaches the user only through the Dashboard and its detail modal.

Inconsistency Reports bypass the API client

Reports.vue imports axios and uses the full URL http://localhost:8001/api/reports/... instead of api.js. The base URL is also hardcoded in api.js, so deploying anywhere other than localhost needs code changes or a Vite proxy.

Demo limits State, security, scale

All data is read-only and re-read from disk only on restart. CORS allows every origin with credentials, and there is no authentication on the API. Every request filters full lists in Python, which is fine for 250 orders but not a design that scales. apply_filters and filter_by_month match order_date by substring.
